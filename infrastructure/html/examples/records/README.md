# HTML 任务记录样例

这些文件演示 Agent 如何把课程制作中的决定、逐页计划、修订边界、来源和交接保存在消费端。内容全部为中性构造，不含实际项目事实、真实用户认可或检查通过记录。无需把整套文件机械复制到每个任务；按工作流需要选择。

| 文件 | 职责 | 使用边界 |
| --- | --- | --- |
| [brief.json](brief.json) | 记录受众基础、理解深度、时间预算和学习结果 | 辅助简报；实际任务对齐仍用任务工具与真实用户原话 |
| [page-plan.json](page-plan.json) | 可执行的完整页面清单，含稳定 ID、模板、插槽和前后回应 | 单页组合可由 `html.materialize --page-plan` 读取；输出占位内容仍需用户核对 |
| [revision.json](revision.json) | 限定基线、目标页和继承范围 | `protected_page_ids` 是修订要求，不是用户已认可的证明；`user_confirmation` 默认空 |
| [source-map.json](source-map.json) | 逐页说明原文、教学归纳和构造示例的边界 | 引用闭合不等于事实正确或得到使用授权 |
| [qa.json](qa.json) | 表达尚未执行的统一检查记录 | `not-run` 与空摘要不能作为通过证据；实际结果由检查工具生成 |
| [handoff.md](handoff.md) | 区分已制作、占位和仅讨论内容，让下次会话续作 | 不是任务状态；暂停/恢复仍通过 `expression.task-record` |
| [source.md](source.md) | 上述记录共用的本地合成来源 | 只演示来源定位，不能包装成研究或项目结论 |

页面计划中 `pages[].id` 是稳定标识，不表示页码。同一模板可使用多次，但每页 ID 必须唯一；目录与显示页码由顺序派生。`responds_to` 只引用已在前文提出的问题，不要求每页都填。`slots` 是纯文本输入，不是任意 HTML 执行入口。

本样例只填标题、摘要、边界等纯文本叶子插槽。`steps`、`evidence-rows`、`actions` 等列表或表格结构插槽由模板原结构承载；物料化后逐项填写并检查语义结构，不能用一个字符串替换整个 `ol` / `tbody` 来伪造结构。未填写的模板示例仍是占位，不能作为完成稿交付。

记录应写入消费端的任务目录或版本目录，项目来源和真实反馈不要回写到基础设施。任务状态、轮次和版本只以任务工具管理的 `task.json` 为准，不能手工维护第二份状态。示例中的 `v001` / `v002` 只是目录惯例，实际版本由任务工具和物料化工具确定。

本组页面计划只使用既有的通用页面，刻意不声明专用学习目标、概念地图或交互练习已实现。它展示任务协议，不是完整教学成品或模板效果验收。
