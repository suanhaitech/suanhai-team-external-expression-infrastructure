# HTML 制作工作流与基础设施

HTML 制作由三个互相衔接的层面共同支撑：`scenarios/` 描述任务用途，`workflows/html/` 组织 Agent 完成任务的过程，`infrastructure/html/` 提供流程节点要选择、装配和检查的页面资产与工具。项目事实、来源材料和最终页面内容由消费端小组资产仓维护。

```text
场景画像：受众变化目标与成功标准
            ↓
消费端内容、来源和授权
            ↓
workflows/html/production/ 主工作流
  澄清 → 内容准备 → 选择资产 → 组装 → 预览迭代 → 检查与收口
            ↓ 调用
infrastructure/html/
  页面模板 + 组件 + 样式 + 运行时 + 工具
            ↓ 物料化
消费端任务目录中的自包含 HTML 版本
```

## 场景、工作流和基础设施

场景回答“为什么表达、面向谁、希望发生什么变化”；工作流回答“Agent 按什么步骤完成”；基础设施回答“有哪些模板、组件、样式和工具可以复用”。场景选择影响内容结构和验收，但不等于交付媒介或阅读容器。

当前由 HTML 主工作流读取的场景画像位于 [`scenarios/`](../scenarios/README.md)：

| 场景 | 主要结果 | 常用归档根 | 内容侧重点 |
| --- | --- | --- | --- |
| 课程学习 | 学习者能理解、讨论或应用主题 | `courses/` | 学习目标、概念递进、例子、练习和迁移 |
| 面向合作方的项目进展沟通 | 合作方理解项目总体变化、证据和协作请求 | `reports/` | 项目经理整体判断、主线结果与限制、跨线影响和下周期结果 |

两种场景都使用同一条 HTML 制作主工作流；可以选择相同页面容器，但内容路径与验收问题不同。场景目录不是 Manifest capability，工作流入口显式读取场景目录并将选定 ID 交给物料化工具记录。

## 工作流与基础设施

工作流描述“怎么完成一次表达任务”。主工作流负责阶段顺序、输入输出、用户确认点和停止条件。具有独立输入输出、可复用且本身包含多步判断的阶段，才适合拆成子工作流；单一确定性操作由工具执行，选择页面资产由主工作流节点完成，事实与发布授权由负责人确认。当前 HTML 制作由 `expression.html-production` 主工作流承载，阶段目前写在同一份 `WORKFLOW.md` 中，尚未拆出注册的子工作流。

基础设施描述“可以复用什么”。HTML 制作的主要资产目录如下：

```text
workflows/html/production/             主工作流与启动入口
infrastructure/html/
├── templates/                          容器、单页模板和完整组合预设
├── components/                        语义组件包及其契约、示例和必要样式
├── styles/                            跨页面复用的基础与响应式样式包
├── runtime-kits/                      随页面复制的公式与交互运行时
└── tools/                             HTML 专用物料化、检查和导出工具
```

根 `manifest.yml` 是消费端发现已实现能力的唯一入口。目录归属帮助理解和维护，不会单独授予调用资格。`workflows/html/production/` 通过 Manifest 能力 ID 使用基础设施；没有注册的阶段或目录不能被描述成可调用能力。

## 页面由什么组成

```text
消费端内容 + 页面模板（结构与样式）+ 默认交互组件 = 自包含 HTML
```

- **内容**：项目事实、文字、数据、图片、来源和授权状态，由消费端提供并核对。
- **页面模板**：页面容器、可组合的单页结构和完整组合预设。`html.project-report-v1` 与兼容预设 `html.presentation-deck-v1` 位于 `templates/presets/`；`html.container.presentation-deck-v1` 与按角色登记的 `html.single-page.*` 能力位于 `templates/containers/` 和 `templates/single-page/`。调用物料化器时，`--page-id` 的出现顺序就是页面顺序。
- **交互组件**：全屏、保存 PDF、显示模式、翻页、备注和原图阅读等阅读操作，由运行时库和容器实现，默认完整装配，按实际内容提供有效入口。
- **语义组件**：阶段状态、指标、来源等可复用信息结构，位于 `components/`，按内容职责选择；不要把它们与交互按钮混称。
- **样式**：设计令牌、基础排版、跨页面布局、屏幕适配和打印规则。组件内部的局部样式仍由组件包管理；模板专属样式仍由模板包管理。
- **运行时**：页面在浏览器中执行的能力及其本地依赖。当前已实现工具栏、KaTeX、全屏、打印入口和原图阅读；默认装配不等于交互已验证。
- **工具**：在制作过程中执行可重复动作，如物料化、视口检查和确定性 PDF 导出；工具不是页面自身带有的按钮。

概念上的职责分层不要求每种文件都拆成单独目录。`templates/containers/` 定义整体阅读方式，`templates/single-page/` 保存可组合的单页模板，`templates/presets/` 保留完整组合预设。消费端要获得可离线复用的结果，工具会按 Manifest 选择版本包并把资源复制到作品目录。页面不依赖读者本机的 submodule 路径。

## 当前实现清单

### 页面与组件

`html.project-report-v1` 是适合连续阅读的项目概览、阶段进展和对外汇报长页模板。`html.presentation-deck-v1` 是适合现场讲解和阶段沟通的多页演示稿模板：逐页聚焦一个判断或问题，页脚标记来源与数据口径，底部提供页码选择、上一页/下一页和进度，支持键盘翻页、讲者备注、自动或手动页面比例以及逐页打印。两种模板有不同的阅读节奏，主工作流依据受众、用途和交付方式选择，不把单页报告里的顶部章节导航复用成演示稿的切页机制。

逐页演示也可选 `html.container.presentation-deck-v1`，并通过多个 `--page-id` 组合封面、目录、过渡、正文、结尾和附录；同一页面变体可以重复。组合模式复制各页面 CSS、替换容器页列表插槽，并在报告记录中保存有序页面 ID、角色、变体和来源。新单页可声明具名组件插槽，完整页面计划用每页 components 绑定插槽和包内组件 ID；不接受未指定页面的顶层 `--component-id`。完整预设调用继续兼容原有组件装配路径。

`html.semantic-components-v1` 当前实际登记六个语义组件：

| ID | 表达内容 |
| --- | --- |
| `content.summary` | 页面或章节摘要 |
| `status.phase` | 阶段、状态和依据 |
| `status.metric` | 有单位和口径的指标 |
| `evidence.claim` | 带核验状态的判断 |
| `evidence.source` | 来源和允许使用范围 |
| `action.next-step` | 下一步、责任人和完成标准 |

该 v1 包还带有设计令牌、基础样式、布局原语和主题入口，是一个版本化安装包，不代表其中每个文件都是独立组件。风险、决策问题、时间线和工作主线等其他组件仍属规划项，未出现在包索引中时不能视为可调用。

### 样式与运行时

`html.responsive-layout-v1` 提供可复用的响应式和打印布局规则，覆盖窄屏、平板、桌面、宽屏、方向、长宽比和安全溢出。运行时显示模式通过 `data-layout-mode` 提供状态；共享布局包解释通用布局类，具体页面模板解释自己的专属类。运行时不应直接依赖 `.report-grid` 等某一个模板的类名。

`html.runtime-kit-v1` 是默认装配的离线页面包，包含锁定版本的 KaTeX、字体、许可证、工具栏样式和脚本。新页面默认具有公式渲染、显示模式、全屏和打开打印对话框保存 PDF 的入口，并同时装配原图阅读器。新增交互通过明确的默认集合增量加入，不要求用户逐个安装；模板与交互的源码仍解耦。确定性 PDF 文件由独立工具 `html.pdf-export` 生成。

第三方运行资源必须随包记录来源、版本、许可证和离线行为。浏览器功能不可用时，应报告 `not-run` 或明确降级，不得伪造成功。

### 工作流与工具节点

| 主工作流阶段 | 主要调用 | 结果或确认点 |
| --- | --- | --- |
| 需求与任务对齐 | `expression.task-loop`、`expression.task-record` | 确认目标、受众、范围、来源和完成标准 |
| 来源与内容准备 | 消费端上下文、来源记录 | 建立可追溯内容结构；未确认内容保持待确认 |
| 选择页面资产 | `html.project-report-v1`、`html.presentation-deck-v1` 或已登记的单页模板、`html.semantic-components-v1`、可选布局和默认运行时 | 按阅读方式选择容器，按表达职责选择单页模板或完整预设，并记录资产版本 |
| 组装页面 | `html.materialize` | 先预览计划，再按同一摘要生成自包含版本 |
| 预览和适配 | `html.viewport-check`、用户反馈 | 记录静态/浏览器检查状态；反馈形成新版本 |
| 导出与评审 | 可选 `html.pdf-export`、负责人评审 | PDF 参数、事实与表达意见及授权分别留痕 |

当前这些阶段由主工作流统一编排。后续仅在真实任务证明阶段可以独立复用后，再把它拆成子工作流；这样可避免为每个步骤增加单独路由成本。

## 消费端输出与来源

页面、项目事实和来源记录留在消费端，输出根按场景和消费端约定选择：课程学习通常使用 `courses/<task-id>/v001/`，项目进展沟通通常使用 `reports/<task-id>/v001/`；既有仓库可按自身规则使用 `works/` 或声明其他安全输出根。

```text
<输出根>/<task-id>/v001/
├── report.yml
├── index.html
├── assets/
├── sources.yml
└── README.md
```

`report.yml` 描述页面任务、场景 ID（如已选择）、所选模板/组件/运行时和授权状态；`materialization.json` 记录场景画像版本及路径、固定基础设施 commit 和复制文件哈希。项目事实仍在消费端上下文和任务记录中。`sources.yml` 为页面中的判断和素材提供定位。格式定义位于 `infrastructure/html/schemas/`，Manifest Schema 等仓库级协议仍留在根 `schemas/`。

公共模板仓默认提供 `reports/` 与 `courses/`；既有消费端可以按自身规则使用 `works/` 或其他安全输出目录。模板和组件物料化后必须成为自包含资源；基础设施 submodule 的 gitlink 固定版本，不能自动跟随远端漂移。

## 质量门

HTML 工作流应执行当前实际可用的检查：

1. Manifest、页面资产元数据和报告内容协议；
2. 插槽、语义组件、来源 ID 与相对路径；
3. 本地资源存在性与远程依赖检查；
4. 桌面、手机、平板、宽屏和打印布局检查；
5. 运行时启用时检查公式、模式切换、全屏和浏览器打印入口；
6. 人工确认事实、表达质量与发布授权。

无障碍自动化检查尚未作为完整能力提供。工具检查通过不代表项目事实正确，也不代表已取得发布授权。

## 统一页面计划与局部修订

页面计划契约在 `infrastructure/html/schemas/page-plan.schema.json`，中性记录样例在 `infrastructure/html/examples/records/`。物料化支持稳定页面 ID、纯文本叶子插槽、默认隐藏备注、来源引用和回应关系，目录从章节过渡页派生；完整页面计划是消费端内容模型，不是新的工作流。模板通过 shared_styles 和 component_slots 显式声明共享样式及可选组件位置。

局部修订沿用同任务、同固定基础设施和同全局配置，从旧版本只读派生，指定可替换页，核对非目标页面不变。插页、重排或全局样式/运行时变化时采用完整修订。检查证据不能从旧版自动升级为新版通过；CDP与Playwright是可选浏览器后端，缺少环境保留 not-run。
