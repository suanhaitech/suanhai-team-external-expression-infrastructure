# HTML 可复用基础设施框架

本文件定义基础设施仓库为不同小组提供 HTML 能力时的长期边界。它不规定任何项目的事实、品牌、客户资料或发布结论。

## 呈现形式与实现材料

仓库先按读者最终接收的**呈现形式**划分，而不是先按模板划分：网页、文档、演示文稿和打印物是并列类型。每种呈现形式再选择实现它的材料或技术；当前网页能力使用 HTML/CSS。模板、组件、主题和媒体资源属于某种呈现形式及其实现材料内部的复用资产。

```text
formats/
├── web/                  # 网页呈现形式
│   └── html/              # 当前网页实现材料
│       ├── page-templates/
│       ├── components/
│       ├── themes/
│       ├── math/
│       └── media/
├── document/              # 与网页并列，当前未实现
└── slides/                # 与网页并列，当前未实现
```

根目录的 `templates/group-asset-repository-v1/` 是用于生成仓库骨架的**仓库模板**，不属于 `formats/` 呈现形式层。目录位置只表达归属；某项能力是否可以调用，仍以根 `manifest.yml` 为准。

## 两个入口

HTML 网页制作有两个互补入口：

- `expression.html-production` 是默认入口，负责任务登记、来源核对、页面选择、版本化预览、检查和人工收口；
- `html.materialize` 根据 Manifest 能力 ID 将选择的页面模板和组件包复制到消费端已对齐任务的版本目录；
- 模板和组件是被工作流选择的资产，负责页面结构、样式和技术表达。

工作流统一生产顺序和证据边界，物料化工具消除重复的文件查找与复制步骤，组件保留页面实现的可组合性。没有工作流时，Agent 可能直接从空白 HTML 开始，难以保证任务、来源和版本可追溯；没有共享模板与组件时，工作流只能规定步骤，无法减少重复制作。

## 能力层次

```text
消费端任务、项目事实、来源和授权
            ↓
report.yml / sources.yml 内容协议
            ↓
页面模板与组件组合
            ↓
设计令牌、布局、媒体和公式
            ↓
离线 HTML / 预览 / 打印 / 检查
```

### 页面基础层

提供 HTML 文档骨架、相对资源加载、浏览器支持范围、主题令牌、中文排版、断点、打印和减少动画规则。基础层应当无项目事实、无远程运行依赖。

### 布局层

提供容器、章节、网格、单栏/双栏、侧栏、全宽媒体、导航、时间线、表格和打印分页。组件必须在手机、平板、桌面和 A4 打印视图中有明确行为。

### 语义组件层

第一批通用组件：

| ID | 作用 |
| --- | --- |
| `content.summary` | 说明页面或章节要让读者理解的核心内容 |
| `status.phase` | 表达阶段、当前状态和判断依据 |
| `status.metric` | 表达有单位、有口径和有来源的指标 |
| `evidence.claim` | 表达可核查的判断及事实状态 |
| `evidence.source` | 展示判断对应的来源和引用范围 |
| `risk.item` | 表达风险、影响、责任人和处理动作 |
| `decision.question` | 表达需要读者讨论或决定的问题 |
| `action.next-step` | 表达下一步、责任主体和完成标准 |
| `process.timeline` | 表达时间、阶段和转折 |
| `process.workstream` | 表达并行工作主线 |

组件是信息对象加展示契约，不是随意命名的卡片。每个组件至少定义必填插槽、可选插槽、状态、来源关联、响应式行为和无障碍要求。当前第一批组件的实现包位于 `formats/web/html/components/core-v1/`。

### 技术表达层

后续按复用需求增加：

- 数学公式：本地 KaTeX 资源、行内/块级公式、可访问替代文本、移动端长公式和打印规则；
- 媒体：本地图片、`alt`、图注、来源 ID、响应式尺寸和版权说明；
- 数据与代码：可滚动代码块、表格、下载资源和静态图表；
- 流程图和架构图：优先使用可离线渲染、可回溯的源文件。

远程 CDN、远程字体和远程图片不是默认依赖。新增第三方资源必须记录版本、许可证、离线行为和检查方式。

## 内容协议

页面产物建议放在消费端。任务循环支持把单个文件或包含 `index.html`、CSS、图片等本地资源的自包含目录作为版本化产物；目录的确定性摘要包含相对路径和文件哈希：

```text
reports/<task-id>/v001/
├── report.yml
├── index.html
├── assets/
├── sources.yml
└── README.md
```

`report.yml` 只描述页面元数据、模板、组件、来源 ID 和授权状态；项目事实仍写在消费端上下文和任务文件中。`sources.yml` 为页面中的判断和素材提供可定位的来源记录。模式文件位于 `schemas/html/`。

## 兼容自建仓和公共模板仓

基础设施不假设消费端有固定目录。工作流先读取消费端根规则，并使用消费端声明的任务和作品目录。公共模板仓默认提供 `reports/`；自建仓可以保留自己的目录，也可以在根目录添加可选配置 `.suanhai/expression.json`：

```json
{
  "schema_version": 1,
  "output_roots": ["web", "reports"]
}
```

配置中的目录名必须是安全的顶层目录名；默认的 `reports`、`works`、`series`、`courses`、`books` 仍然兼容。配置只能增加作品输出位置，不能授权写入 `vendor`、`.git`、`context` 或 `tasks`。当消费端使用 `expression.task-record` 时，这一配置还会进入每次作品路径校验和历史哈希验证。

自建仓只要能提供：

- 一个任务记录位置；
- 一个版本化 HTML 产出位置（默认输出根或 `.suanhai/expression.json` 声明的输出根）；
- 一个来源和评审记录位置；
- 根 `AGENTS.md` 对 submodule 和 Manifest 的读取规则。

模板和组件复制到消费端时应变成自包含产物。页面发布或移出消费端后不应依赖读者本机的 submodule 路径。

## Manifest 与版本

Manifest 只登记可被消费端发现的完整能力包：模板、工具、检查器和工作流。组件作为模板包的内部契约或组合包维护，不逐个登记每个 CSS 类。

每个完整包应声明：

- 能力 ID 和版本；
- 入口文件；
- 所需资源和离线要求；
- 组件依赖；
- 浏览器和打印支持范围；
- 许可证与上游来源；
- 示例和检查方法。

消费端以 gitlink 固定基础设施提交。`develop` 用于试用，`main` 用于稳定引用；升级沿用 `consumer.submodule-update`，不能让页面自动漂移到远端最新版本。

## 质量门

HTML 能力成熟后，工作流应依次接入：

1. Manifest、模板元数据和内容协议检查；
2. HTML 标题层级、插槽、来源 ID 和相对路径检查；
3. 本地资源、外部请求和离线打开检查；
4. 桌面、手机、平板和打印视图检查；
5. `alt`、表头、对比度、键盘焦点和减少动画检查；
6. 人工事实、表达和发布授权评审。

工具检查通过不等于页面事实正确或已获授权。任何失败都应阻止工作流进入完成状态，或明确记录为尚未实现的检查。
