# HTML 制作工作流与基础设施

HTML 制作由两类共享能力共同支撑：`workflows/html/` 组织 Agent 完成任务的过程，`infrastructure/html/` 提供流程节点要选择、装配和检查的页面资产与工具。项目事实、来源材料和最终页面内容由消费端小组资产仓维护。

```text
消费端内容、来源和授权
            ↓
workflows/html/production/ 主工作流
  澄清 → 内容准备 → 选择资产 → 组装 → 预览迭代 → 检查与收口
            ↓ 调用
infrastructure/html/
  页面模板 + 组件 + 样式 + 运行时 + 工具
            ↓ 物料化
消费端任务目录中的自包含 HTML 版本
```

## 两条结构轴

工作流描述“怎么完成一次表达任务”。主工作流负责阶段顺序、输入输出、用户确认点和停止条件。具有独立输入输出、可复用且本身包含多步判断的阶段，才适合拆成子工作流；单一确定性操作由工具执行，选择页面资产由主工作流节点完成，事实与发布授权由负责人确认。当前 HTML 制作由 `expression.html-production` 主工作流承载，阶段目前写在同一份 `WORKFLOW.md` 中，尚未拆出注册的子工作流。

基础设施描述“可以复用什么”。HTML 制作的主要资产目录如下：

```text
workflows/html/production/             主工作流与启动入口
infrastructure/html/
├── page-templates/                    完整页面结构与模板专属样式
├── components/                        语义组件包及其契约、示例和必要样式
├── styles/                            跨页面复用的基础与响应式样式包
├── runtime-kits/                      随页面复制的公式与交互运行时
└── tools/                             HTML 专用物料化、检查和导出工具
```

根 `manifest.yml` 是消费端发现已实现能力的唯一入口。目录归属帮助理解和维护，不会单独授予调用资格。`workflows/html/production/` 通过 Manifest 能力 ID 使用基础设施；没有注册的阶段或目录不能被描述成可调用能力。

## 页面由什么组成

```text
消费端内容 + 页面模板 + 语义组件/控件 + 样式 + 可选运行时 = 自包含 HTML
```

- **内容**：项目事实、文字、数据、图片、来源和授权状态，由消费端提供并核对。
- **页面模板**：页面骨架、内容插槽和模板专属视觉组合。当前实现 `html.project-report-v1`。
- **组件**：可复用的信息结构或交互，例如阶段状态、指标、来源、全屏控件。组件可以携带自身必需的 CSS/JavaScript，保持可安装包完整。
- **样式**：设计令牌、基础排版、跨页面布局、屏幕适配和打印规则。组件内部的局部样式仍由组件包管理；模板专属样式仍由模板包管理。
- **运行时**：页面在浏览器中执行的能力及其本地依赖。当前候选包包含 KaTeX 公式渲染、显示模式、全屏和浏览器打印入口。
- **工具**：在制作过程中执行可重复动作，如物料化、视口检查和确定性 PDF 导出；工具不是页面自身带有的按钮。

概念上的职责分层不要求每种文件都拆成单独目录。消费端要获得可离线复用的结果，工具会按 Manifest 选择完整版本包并把资源复制到作品目录。页面不依赖读者本机的 submodule 路径。

## 当前实现清单

### 页面与组件

`html.project-report-v1` 是项目概览、阶段进展和对外汇报页面模板。模板自身的 `styles.css` 和 `report.css` 负责该页面的具体视觉表现。

`html.semantic-components-v1` 当前实际登记六个语义组件：

| ID | 表达内容 |
| --- | --- |
| `content.summary` | 页面或章节摘要 |
| `status.phase` | 阶段、状态和依据 |
| `status.metric` | 有单位和口径的指标 |
| `evidence.claim` | 带核验状态的判断 |
| `evidence.source` | 来源和允许使用范围 |
| `action.next-step` | 下一步、责任人和完成标准 |

该 v1 包还带有设计令牌、基础样式、布局原语和主题入口，是一个版本化安装包，不代表其中每个文件都是独立组件。风险、决策问题、时间线和工作主线等其他组件仍属规划项，未出现在包索引中时不能视为可调用。

### 样式与运行时

`html.responsive-layout-v1` 提供可复用的响应式和打印布局规则，覆盖窄屏、平板、桌面、宽屏、方向、长宽比和安全溢出。运行时显示模式通过 `data-layout-mode` 提供状态；共享布局包解释通用布局类，具体页面模板解释自己的专属类。运行时不应直接依赖 `.report-grid` 等某一个模板的类名。

`html.runtime-kit-v1` 是可选的离线页面包，包含锁定版本的 KaTeX、字体、许可证、工具栏样式和脚本。选择该包的页面才具有公式渲染、显示模式、全屏和打开打印对话框保存 PDF 的入口。它不会自动出现在所有 HTML 页面中。确定性 PDF 文件由独立工具 `html.pdf-export` 生成。

第三方运行资源必须随包记录来源、版本、许可证和离线行为。浏览器功能不可用时，应报告 `not-run` 或明确降级，不得伪造成功。

### 工作流与工具节点

| 主工作流阶段 | 主要调用 | 结果或确认点 |
| --- | --- | --- |
| 需求与任务对齐 | `expression.task-loop`、`expression.task-record` | 确认目标、受众、范围、来源和完成标准 |
| 来源与内容准备 | 消费端上下文、来源记录 | 建立可追溯内容结构；未确认内容保持待确认 |
| 选择页面资产 | `html.project-report-v1`、`html.semantic-components-v1`、可选布局和运行时 | 记录选用的资产及版本 |
| 组装页面 | `html.materialize` | 先预览计划，再按同一摘要生成自包含版本 |
| 预览和适配 | `html.viewport-check`、用户反馈 | 记录静态/浏览器检查状态；反馈形成新版本 |
| 导出与评审 | 可选 `html.pdf-export`、负责人评审 | PDF 参数、事实与表达意见及授权分别留痕 |

当前这些阶段由主工作流统一编排。后续仅在真实任务证明阶段可以独立复用后，再把它拆成子工作流；这样可避免为每个步骤增加单独路由成本。

## 消费端输出与来源

页面、项目事实和来源记录留在消费端，输出默认使用 `reports/<task-id>/v001/`：

```text
reports/<task-id>/v001/
├── report.yml
├── index.html
├── assets/
├── sources.yml
└── README.md
```

`report.yml` 描述页面任务、所选模板/组件/运行时和授权状态；项目事实仍在消费端上下文和任务记录中。`sources.yml` 为页面中的判断和素材提供定位。格式定义位于 `infrastructure/html/schemas/`，Manifest Schema 等仓库级协议仍留在根 `schemas/`。

公共模板仓默认使用 `reports/`；既有消费端可以按自身规则使用 `works/` 或其他安全输出目录。模板和组件物料化后必须成为自包含资源；基础设施 submodule 的 gitlink 固定版本，不能自动跟随远端漂移。

## 质量门

HTML 工作流应执行当前实际可用的检查：

1. Manifest、页面资产元数据和报告内容协议；
2. 插槽、语义组件、来源 ID 与相对路径；
3. 本地资源存在性与远程依赖检查；
4. 桌面、手机、平板、宽屏和打印布局检查；
5. 运行时启用时检查公式、模式切换、全屏和浏览器打印入口；
6. 人工确认事实、表达质量与发布授权。

无障碍自动化检查尚未作为完整能力提供。工具检查通过不代表项目事实正确，也不代表已取得发布授权。
