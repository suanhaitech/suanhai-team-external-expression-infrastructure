# `consumer.group-asset-create-and-initialize` 工作流 Harness

本入口约束 Agent 如何执行“小组资产仓创建并初始化”这项复合能力。目标仓可能还不存在，不能假定 Agent 能从目标仓的 Manifest 发现本工作流。

## 外部首次启动

组长直接发送同目录的 [`CREATE_AND_INITIALIZE.md`](CREATE_AND_INITIALIZE.md)。该提示词是独立的首次启动材料，明确建仓参数、工具检查、GitHub Template Generate、递归克隆、submodule 校验、初始化访谈和授权边界。Agent 应按提示词完整执行，不要求组长先手工克隆基础设施仓。

如果该提示词并未随用户消息提供，且当前环境尚未读取它，不猜测建仓参数或自行创建远程仓库；先读取该提示词，或请负责人补齐必要参数。

## 工作流路由

1. 先判断用户要创建的是新小组资产仓，还是继续使用已有仓库。已有仓库不重复创建，改走适用的接入或初始化流程。
2. 对新仓创建，遵循提示词核对组织、仓库名、可见性、本地路径、账号及工具环境；缺少必要参数时集中询问。
3. 仅通过公开模板生成 API 创建仓库，并递归克隆。发生名称冲突、权限不足、目录冲突或环境失败时停止并报告，不换名、改可见性或覆盖目标。
4. 从模板父仓 gitlink 恢复并核对固定基础设施版本。不得执行 `git submodule update --remote` 或自行选择新版本。
5. 在新仓根目录读取 `README.md` 和 `AGENTS.md`，确认 Manifest 与 onboarding 入口后，调用 `consumer.group-asset-onboarding` 逐步完成上下文初始化。
6. 初始化候选和待确认事项留在消费端工作区供组长审阅；是否提交或推送由负责人另行决定。

## 停止条件

缺少必要输入、Agent 工具环境无法使用、模板来源不正确、创建结果不确定、submodule/gitlink 不一致、工作区出现未预期修改，或 Manifest 缺少依赖能力时停止并保留现场。不得将远程仓创建的授权扩展为组织权限变更、初始化事实确认、提交推送或对外发布。
