# HTML 对外表达制作工作流

状态：`implemented / experimental`

能力 ID：`expression.html-production`

## 目标

把一次 HTML 制作任务组织成可追溯、可预览、可修订和可收口的生产过程。工作流适用于：

- 使用公共小组资产仓模板的消费端；
- 已有自己的目录结构、但已经接入基础设施 submodule 的消费端；
- 使用不同 Agent 客户端的本地工作区。

工作流负责阶段、确认点和边界；模板、组件、预览器和检查器负责具体能力。项目事实、来源文件、素材和评审记录始终留在消费端仓库。

## 输入

- 用户对网页目标的自然语言需求；
- 目标受众、用途、交付形式和预期时间；
- 文档、链接、图片、数据、代码、会议记录等候选材料；
- 消费端仓库的项目上下文、任务目录和发布边界；
- 当前固定 submodule 中 Manifest 声明的能力。

用户可以在标准模板仓库或既有仓库中启动流程。工作流不得假定消费端一定有 `reports/`；应先读取消费端 `AGENTS.md`、任务目录约定和可选的 `.suanhai/expression.json`，再选择已约定的输出根目录。默认报告输出在任务简报中登记为稳定根 `reports/<task-id>`，工具按当前修订生成 `v001`、`v002` 等版本目录；旧消费端可以使用其兼容的 `works/<task-id>`。

## 阶段与停止条件

### 1. 登记任务

Agent 先使用 `expression.task-record` 创建任务，不直接写 HTML。任务至少记录目标、受众、用途、范围、输出位置、完成标准和候选来源。未知项保留为空或标记为待确认，不得猜测。

如果用户只要求调查或比较方案，停在任务澄清或内容结构阶段，不创建页面产物。

### 2. 对齐简报

Agent 读取来源清单，提出会改变页面方向的问题，并把用户实际确认原话记录到任务历史。至少需要对齐：

- 页面面向谁、用于什么场景；
- 页面要促成读者理解、决定或行动的结果；
- 覆盖的时间范围和内容边界；
- 哪些材料允许使用、哪些材料只供内部核对；
- 交付目录、版本规则和完成标准。

受众、用途、范围或授权发生变化时，按任务循环回到 `clarifying`，不得在旧简报下继续制作。

### 3. 来源与内容结构

Agent 为候选来源建立 `sources.yml`，记录路径或 URL、版本/日期、来源类型、使用许可、可引用范围和核对状态。将该清单或其他实际来源文件路径登记到任务简报的 `sources` 中，确保任务工具可以验证来源文件存在。再生成不含项目事实的内容结构：页面目标、章节、语义组件、核心判断和待确认内容。

只有已登记且允许使用的来源才能进入页面；有来源不等于已经核验，用户口述不等于发布授权。

### 4. 选择页面与组件

Agent 从当前 Manifest 选择已实现的页面模板和组件包，读取其入口文档与元数据。选择依据是任务的受众、用途和内容结构，不根据模板名称猜测能力。

组件选择应记录在 `report.yml` 中。先选择 Manifest 中的组件包，再从其 `index.yml` 选择稳定的语义组件 ID；物料化工具会把选中的片段插入页面的组件插槽，并同时复制完整组件包，后续可按契约继续调整。组件是语义信息对象，不是任意视觉卡片；每个组件应能关联来源状态、响应式行为和无障碍要求。

当 Manifest 注册 `html.materialize` 时，应调用 `tools/html-materialize/materialize_html.py` 物料化已选模板和组件，不要逐文件手工复制。先 dry-run，核对目标目录、能力版本和基础设施 commit，再把预览返回的 `plan_sha256` 与 `task_record_version` 一并传给 `--apply`。工具要求任务已进入 `working`，并从已经对齐的 `brief.output` 推导任务修订路径。遇到缺少能力、路径不匹配、gitlink 不一致或目标冲突时停止，不绕开工具直接复制。

### 5. 生成首版

Agent 在消费端任务目录创建 `v001`，至少包含：

```text
reports/<task-id>/v001/
├── report.yml
├── index.html
├── assets/
├── sources.yml
└── README.md
```

HTML 和 CSS 使用相对路径，资源自包含，不依赖 CDN、远程字体、远程图片或运行时网络服务。物料化结果中的 `materialization.json` 保留共享资产来源 commit 与文件哈希；模板占位内容必须被真实内容替换，不能把占位文字当作项目事实。

### 6. 预览与反馈

Agent 生成本地预览或截图，至少检查桌面、手机和打印视图。用户反馈按以下类别记录：内容、事实/来源、结构、视觉、屏幕适配、打印/无障碍和范围变化。

局部反馈生成新版本目录，例如 `v002`，不得覆盖旧版本；范围变化必须回到澄清阶段。没有浏览器预览或检查器时，必须明确报告该能力尚未实现，不能宣称已完成验证。

### 7. 检查与评审

Agent 在进入 `review` 前执行当前已实现的检查：文件存在、路径在任务目录内、来源 ID 闭合、HTML 结构和本地资源可解析。未来增加的预览、响应式、无障碍和公式检查也应在这里接入。

检查通过不代表专业事实正确，也不代表对外发布授权。Chaos 或消费端负责人分别完成项目事实、表达质量和发布授权确认。

### 8. 收口与续作

用户确认当前版本后，使用任务循环记录确认原话、产出路径、SHA-256 和仍存限制，再进入 `completed`。以后可通过任务编号恢复；新一轮修订保留历史版本并使用新的 `vNNN` 目录。

## 不得做的事情

- 不得在没有任务简报和来源边界时直接生成对外页面；
- 不得把项目专属事实、客户材料或未经授权的素材写入基础设施 submodule；
- 不得自动跟随 submodule 远端分支或擅自升级依赖；
- 不得覆盖已经评审或确认的版本；
- 不得因为 HTML 检查通过就宣称已经获得发布授权；
- 不得自动提交、推送、部署或发布，除非用户另行明确授权。

## 依赖

- `expression.task-loop`
- `expression.task-record`
- `html.project-report-v1` 或当前 Manifest 中适合任务的页面模板；
- 当前 Manifest 中已实现的 HTML 组件、预览和检查能力。
