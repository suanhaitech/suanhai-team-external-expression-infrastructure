# HTML 制作启动提示词

把本文件全文发送给你平常使用的 Agent，并在同一消息后补充网页目标、受众、用途、材料链接和限制。请在消费端资产仓库根目录执行。

```text
你现在在一个小组对外表达资产仓库中工作。请把本次请求作为一次 HTML 制作任务处理。

开始前必须依次读取：
1. 当前仓库根目录的 AGENTS.md、README.md；
2. context、tasks、reports（或当前仓库规定的作品目录）；
3. 当前基础设施 submodule 根目录下的 `manifest.yml`；
4. 当前基础设施 submodule 根目录下的 `workflows/html/production/WORKFLOW.md`；
5. 被选择模板或组件的入口文档。

不要一开始就写 HTML。先：
- 登记或恢复任务；
- 检查任务工具要求的 context/ 和 tasks/ 是否存在；缺少时先报告并取得我对建立兼容目录的确认，不擅自迁移旧目录；
- 盘点我提供的文档、链接、图片、数据和其他上下文；
- 将来源清单存成消费端任务可读取的文件，并把该文件路径登记进任务来源；
- 记录来源路径、版本/日期、使用范围和待核对状态；
- 在来源/作品首次登记摘要前，核对本仓 `.gitattributes` 的有效字节保护范围；缺口按固定 Manifest 的 `consumer.asset-bytes` 默认只读预览，遵循本轮已有授权显式应用匹配摘要，不覆盖原规则、不重写历史文件或执行 renormalize；
- 主动推荐内容与资产，只提材料不能确定且影响受众、用途、范围、页面结果、授权或完成标准的关键问题；复用我已经认可的方案，不重复确认；
- 新任务默认分页，采用 html.container.presentation-deck-v1 + page-plan.json + html.single-page.*；只有我明确要求连续阅读、传阅或查阅时选择长页，既有长页不自动改版；分别对齐交付是空白模板还是完整报告；演示稿使用底部页码选择、上一页和下一页，不用顶部导航切页；
- 默认配齐全部已实现交互：显示模式、全屏、保存 PDF、原图阅读，以及分页容器的翻页、比例和备注；主动介绍使用方式与限制，不要求我逐项指定安装；
- 对照 `scenarios/catalog.json` 识别表达场景并读取画像；当前有“课程学习”和“面向合作方的项目进展沟通”，不要把 HTML、PDF 或页面容器当成场景；
- 如果制作项目周期汇报，确认汇报周期、数据截止时间和主汇报人，从授权主线材料收集上期目标、本期结果、证据/限制、依赖及下期目标；缺少或未核验的信息标注待确认；
- 若为课程，确认受众已有基础、需要达到的理解深度、时间预算和参与方式，不机械规定页数；
- 用自己的话复述任务并等待我的确认。

确认后再：
- 将已确认的场景画像转成覆盖当前整稿的逐页计划，列出稳定页面 ID、页面目标、核心信息、来源/证据、候选页面职责或资产、选用资产与定制理由、场景验收信号；目录和显示页码由顺序派生，问题与回应可用 responds_to 关联；在选择页面资产前把计划交给我确认；
- 单页组合保存 page-plan.json，以 artifact_kind 记录 template/report，用 candidate_assets、customization_reason、acceptance_signals 补足复用选择；参考 infrastructure/html/examples/records/ 的简报、页面计划、修订、来源映射、QA 和交接样例，但不要把样例当成真实事实或用户确认；
- 项目总汇报先讲总体判断和关键变化，再讲主线证据、跨线影响、协作请求和下周期结果；优先自由组合项目总览页、可重复主线页和跨线协作页，不固定主线数和总页数。事实核验归各线负责人，整体口径归项目经理；
- 制作项目汇报前读取 docs/project-report-reusable-assets.md：证据页一页一个主判断，同一判断可有多项互补证据，逐项写来源版本、定位、支持关系和数字口径；独立判断拆页，适用边界和尚未证明内容留正文，总体状态不能覆盖正文已知缺口；
- 多项文字/数据证据选 conclusion-evidence-v1，图像承担主要证明任务时选 figure-analysis-v1；默认主证据图片占主要区域、关键标注可读且比例完整，放大只用于读细节。每页用 pages[].notes 准备串场句、关键数字、可能追问和答复来源；备注随文件交付，不放未获准披露信息；
- 区分画像中的必须项、默认建议和按需选择；如现有基础设施缺少匹配资产，标记缺口并与我确认处理方式，不把缺口伪装成已支持能力；
- 从固定 Manifest 中选择已实现的模板和组件；
- 对已登记场景调用物料化工具时传入 `--scenario-id`，让场景 ID 与版本进入作品记录；输出根仍按消费端约定和已对齐简报决定；
- 长页报告选择 `html.project-report-v1`，逐页讲解可以选择兼容预设 `html.presentation-deck-v1`，或选择 `html.container.presentation-deck-v1` 并按 `--page-plan <相对路径>` 组合封面、目录、过渡、内容、结尾和附录；初步选型仍可重复传入 `--page-id`，两种输入不能混用。复用容器自带翻页、比例选择和打印规则，不另写一套导航；单页组件在计划的 components 中指定已声明的页面插槽，不向组合模式传预设专用的顶层 `--component-id`；
- 调用 Manifest 中的 `html.materialize`，先预览计划，再在用户确认后按相同计划摘要复制模板与组件；
- 页面需要跨设备适配时，在物料化命令中选择 `html.responsive-layout-v1`，不要手工从未知路径复制 CSS；
- 演示页复用已声明的共享页框 `html.presentation-foundation-v1`，按需通过 `--layout-id` 选择，暖白主题使用 `--theme editorial-warm`；布局与运行时参数可重复，不自行复制一套公共字阶；
- 物料化默认装配 `html.runtime-kit-v1` 和 `html.image-viewer-v1`；运行时参数用于增量扩展，使用声明运行时插槽的模板，不重写已有工具栏或交互脚本；
- 原图阅读器默认装配；为本地原图链接添加 `data-source-image`，检查适应窗口、原始尺寸、缩放、拖动、关闭、焦点返回及翻页键隔离。没有图片时能力就绪，不添加空的图片按钮；
- 生成内容结构和 report.yml，记录所选模板、组件、布局包及默认及增量运行时包；
- 在任务简报登记的输出根下创建工具生成的 `vNNN` 自包含 HTML 版本目录；课程学习通常使用 `courses/<task-id>`，项目进展沟通通常使用 `reports/<task-id>`，并以消费端仓库规则为准；
- 如果作品目录不在 reports/、works/、series/、courses/、books/ 下，先按 infrastructure/html/schemas/consumer-expression.schema.json 建立 .suanhai/expression.json 声明额外的安全顶层目录；
- 只使用相对路径和已登记来源，不使用 CDN、远程字体或远程图片；
- 对本版已经取得的原图和衍生素材，调用 `html.source-assets register` 默认预览，核对摘要后显式应用，并在评审前 `validate`。登记原始/衍生关系、转换和使用边界；工具不下载URL、不判断版权，素材规格和语义source-map分别保留；
- 正文只呈现关键判断、帮助理解的解释和必要条件；串场和扩展说明可放默认隐藏备注，长证据与完整出处可放附录/source-map，不强制每页显示来源小字；隐藏备注也随文件交付，不能承载未授权信息；
- 调用 `html.viewport-check` 做静态资源和默认多视口检查，演示稿用 `--all-pages --interactions --full-page --fail-on-overflow` 和 `--artifact-kind template|report` 检查整稿。`--backend auto` 可用Playwright或本机Chrome/Edge/Chromium CDP，不因为缺Playwright就直接判浏览器检查不可执行；如果要交付 PDF，在确认纸张、方向和页边距后调用 `html.pdf-export`；
- 逐页查看 `pageVerticalOverflow` 与 `navigationOverlap`：前者表示内容超过当前可视画布，应调整信息密度、版式或拆页，后者表示正文与固定控制栏相交；不能靠隐藏溢出、删去必要事实或只保留页内滚动把失败写成通过；
- 需要整稿评审时生成本轮截图与 `--contact-sheet` 离线图册；需要版本并排时用 `--compare-with <旧检查JSON>`，人工核对插页后的对应关系，不把联系表当作自动审美验收；
- 进行可用的结构、资源、来源、响应式和打印检查；将浏览器缺失记录为 `not-run`，不把它写成通过；
- 演示稿逐页检查底部翻页、页码跳转、首尾禁用、键盘导航、窄屏单栏和打印全部内容；要求一页一纸时先拆分过长页，再检查实际导出 PDF，不能靠隐藏溢出来保持比例；讲者备注随 HTML 文件一起交付，未获准对读者公开的信息不能放进备注；
- 按 docs/html-presentation-safe-area-test.md 实际验收全屏期间底部控制栏持续隐藏且不可聚焦、鼠标/触摸到下沿不唤出、画布比例稳定、Esc退出后恢复；复用现有容器，不新增全局指针拦截。未执行真实输入或焦点检查时逐项保留 not-run；
- 默认装配后，先核对源码中的 `data-runtime-toolbar` 容器和本地运行时资源，再在浏览器运行后的 DOM 核对动态注入的全屏和 PDF 按钮；实际观察公式渲染，逐项操作显示模式、全屏进入/退出和“保存 PDF”，记录结果。没有执行或环境不支持时逐项标为 `not-run`，按钮存在不等于交互通过；页面内“保存 PDF”打开浏览器打印对话框，需要交付 PDF 文件时仍使用 `html.pdf-export`；
- 遵守 infrastructure/html/templates/FILLING.md 的填写协议，正文、data-state 与可见标签同步，作者提示放 README，空白模板用隔离合成数据验证填写路径；长页用 --interactions --full-page 保存全长证据，说明未执行项与资源摘要范围；
- 提供本地预览或截图供我反馈。

我反馈后不要覆盖旧版本。局部反馈记录基线和目标页面 ID，支持时用 --baseline-version v001 --replace-page <稳定ID> 和完整 --page-plan 生成新的 vNNN，核对非目标页和已认可内容没有改变；范围变化回到任务澄清。认可某一页只确认该范围；只有我明确验收本轮完整交付范围后，才记录任务完成，完成不等于专业验收或对外发布授权。尚未制作的章节、占位页和待确认内容明确登记；暂停与续作复用现有 pause/resume，不建立新的状态机。

任何已有任务写入前，先读取最新 version 并携带 --expect-version。不要自动提交、推送、部署、升级 submodule 或修改基础设施仓库。遇到规则、来源、版本或检查冲突时停止并告诉我。
```

这是一段一次性启动入口；任务建立后，后续会话应优先通过任务编号恢复，而不是重新发送整段提示词。
