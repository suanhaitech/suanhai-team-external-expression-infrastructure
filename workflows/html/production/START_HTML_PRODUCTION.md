# HTML 制作启动提示词

把本文件全文发送给你平常使用的 Agent，并在同一消息后补充网页目标、受众、用途、材料链接和限制。请在消费端资产仓库根目录执行。

```text
你现在在一个小组对外表达资产仓库中工作。请把本次请求作为一次 HTML 制作任务处理。

开始前必须依次读取：
1. 当前仓库根目录的 AGENTS.md、README.md；
2. context、tasks、reports（或当前仓库规定的作品目录）；
3. 当前基础设施 submodule 根目录下的 `manifest.yml`；
4. 当前基础设施 submodule 根目录下的 `workflows/html/production/WORKFLOW.md`；
5. 被选择模板或组件的入口文档。

不要一开始就写 HTML。先：
- 登记或恢复任务；
- 检查任务工具要求的 context/ 和 tasks/ 是否存在；缺少时先报告并取得我对建立兼容目录的确认，不擅自迁移旧目录；
- 盘点我提供的文档、链接、图片、数据和其他上下文；
- 将来源清单存成消费端任务可读取的文件，并把该文件路径登记进任务来源；
- 记录来源路径、版本/日期、使用范围和待核对状态；
- 向我提问受众、用途、范围、页面结果、授权边界和完成标准；
- 确认是否需要数学公式、显示模式切换、全屏和页面内“保存 PDF”入口；这些是可选运行时功能，不默认添加到所有页面；
- 用自己的话复述任务并等待我的确认。

确认后再：
- 从固定 Manifest 中选择已实现的模板和组件；
- 调用 Manifest 中的 `html.materialize`，先预览计划，再在用户确认后按相同计划摘要复制模板与组件；
- 页面需要跨设备适配时，在物料化命令中选择 `html.responsive-layout-v1`，不要手工从未知路径复制 CSS；
- 需要已确认的运行时功能时，显式传入 `--runtime-kit-id html.runtime-kit-v1`，使用支持运行时插槽的模板；不要自行重写基础设施已经提供的工具栏、公式渲染或交互脚本；
- 生成内容结构和 report.yml，记录所选模板、组件、布局包及可选运行时包；
- 在任务简报登记的输出根（默认 `reports/<task-id>`）下创建工具生成的 `vNNN` 自包含 HTML 版本目录；
- 如果作品目录不在 reports/、works/、series/、courses/、books/ 下，先按 infrastructure/html/schemas/consumer-expression.schema.json 建立 .suanhai/expression.json 声明额外的安全顶层目录；
- 只使用相对路径和已登记来源，不使用 CDN、远程字体或远程图片；
- 调用 `html.viewport-check` 做静态资源和默认多视口检查；如果要交付 PDF，在确认纸张、方向和页边距后调用 `html.pdf-export`；
- 进行可用的结构、资源、来源、响应式和打印检查；将浏览器缺失记录为 `not-run`，不把它写成通过；
- 选择运行时包后，先核对源码中的 `data-runtime-toolbar` 容器和本地运行时资源，再在浏览器运行后的 DOM 核对动态注入的全屏和 PDF 按钮；实际观察公式渲染，逐项操作显示模式、全屏进入/退出和“保存 PDF”，记录结果。没有执行或环境不支持时逐项标为 `not-run`，按钮存在不等于交互通过；页面内“保存 PDF”打开浏览器打印对话框，需要交付 PDF 文件时仍使用 `html.pdf-export`；
- 提供本地预览或截图供我反馈。

我反馈后不要覆盖旧版本。局部反馈生成新的 vNNN，范围变化回到任务澄清。只有我明确确认当前版本后，才记录任务完成；完成不等于专业验收或对外发布授权。

任何已有任务写入前，先读取最新 version 并携带 --expect-version。不要自动提交、推送、部署、升级 submodule 或修改基础设施仓库。遇到规则、来源、版本或检查冲突时停止并告诉我。
```

这是一段一次性启动入口；任务建立后，后续会话应优先通过任务编号恢复，而不是重新发送整段提示词。
