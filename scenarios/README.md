# 表达场景

场景描述一次“实践认知与对外表达”任务为什么发生、面向谁、希望受众发生什么变化，以及应该如何判断结果有效。

场景是任务画像，不是工作流、模板或工具：

```text
场景画像
  -> 选择主工作流和内容结构
  -> 主工作流调用模板、组件、样式和工具
  -> 消费端保存项目事实、来源、作品和评审记录
```

场景不进入 `manifest.yml` 的 `capabilities`，因为读取场景不会授予执行能力。场景入口由工作流文档显式引用；只有已经实现并可验证的工作流、模板、工具和检查才登记到 Manifest。

## 当前主场景

场景围绕实践或认知对象展开，并定义受众、期望变化、内容路径和成功标准。当前接入两个具体场景：

| 场景 | 受众变化目标 | 默认输出根 | 当前可复用资产 |
| --- | --- | --- | --- |
| `expression.scenario.course-learning-v1` | 让学习者理解概念、形成判断并能讨论或应用 | `courses/` | 逐页演示容器、封面、目录、过渡、方法、证据、结尾、附录 |
| `expression.scenario.project-progress-communication-v1` | 让合作方理解项目总体变化、各主线证据、跨线影响和协作请求 | `reports/` | 项目汇报长页、逐页演示容器及现有语义组件 |

两者共享来源治理、事实边界、响应式、离线资源、打印和版本化规则。课程还需要学习目标、示例、练习和迁移；项目进展沟通还需要项目经理的整体判断、各工作主线的证据与限制、跨线依赖、协作请求和结果导向的下周期计划。主汇报人承担整合和口径责任，不替代主线负责人核验专业事实或具备对外发布授权。未登记为能力的页面类型只能作为待补基础设施，不得在产出记录中宣称已经可调用。

## 场景画像契约

每个场景目录包含：

```text
<scenario>/
├── scene.yml       # 稳定 ID、版本和任务画像
└── README.md       # Agent 读取的解释、结构和验收边界
```

`scene.yml` 的 `id` 是作品元数据中可选的 `scenario_id`；它必须与目录中登记的稳定场景一致。场景文件不写项目名称、客户资料或具体事实。
