# 课程学习

## 场景到 HTML 决策映射

本画像描述课程学习对 HTML 内容和验收提出的要求，不指定唯一模板、页面比例、配色或阅读容器。Agent 应先把学习目标转成逐页计划，再按实际讲解或阅读情境选择基础设施资产。

| 决策 | 要求级别 | 对 HTML 的映射 | 可检查信号 |
| --- | --- | --- | --- |
| 学习结果 | 必须 | 明确学习者看完后能解释、判断、讨论或完成什么；用可观察动作表述 | 目标不是“了解主题”等不可判断措辞 |
| 内容路径 | 必须 | 按学习者理解过程组织，而不是按来源材料顺序缩写；通常由问题引入，经过概念/机制解释与示例，再到练习或讨论、回顾和迁移 | 逐页计划说明前后页的认知关系，必要概念未跳步；可删的重复页不承担新的学习目标 |
| 单页职责 | 必须 | 每页对应一个主要学习动作，并写明本页目标、核心信息和与前后页的关系 | 标题、内容和学习动作一致；单页不堆叠多个无关目标 |
| 解释与例子 | 必须 | 对关键概念给出分步解释，并用例子、案例或反例帮助理解；例子需标明是来源材料还是讲者构造 | 抽象主张能追溯到解释或例子；构造示例未伪装成项目事实 |
| 学习者参与 | 必须 | 至少安排一个练习、自检、思考题或讨论动作；若形式不适用，简报中说明原因并调整验收标准 | 页面要求学习者做出可描述的回答、判断或操作 |
| 小结与迁移 | 默认建议 | 在结尾回顾关键理解，并给出一个可执行的迁移问题或后续实践 | 学习者知道如何把概念用于新问题；不适用时说明原因 |
| 来源与判断边界 | 必须 | 区分来源原文、来源数据、讲者归纳、团队判断和待验证内容；读者可见内容与讲者备注分开确认 | 重要事实有来源或明确待核状态；未经授权的信息不进入备注 |
| 阅读节奏 | 默认建议 | 从低门槛问题逐步增加概念复杂度；控制每页信息量，为练习和回顾留空间 | 连续页面不是同一段长文的机械切片；练习前有足够解释 |
| 视觉方向 | 默认建议 | 用层级、留白和图示帮助看出概念关系与学习阶段；遵循消费端品牌约束，不由场景 ID 自动指定主题或配色 | 视觉强调服务于理解，不掩盖证据状态或制造未经支持的结论 |
| 阅读容器与交互 | 按需选择 | 根据自学查阅、课堂讲解或讨论分享选择长页/逐页容器；练习交互、公式和全屏等能力只有在任务需要且资产已实现时才选择 | 选择理由来自使用方式；未实现能力列为资产缺口，不模拟已支持功能 |

### 页面职责与现有资产

以下是候选映射，不是场景 ID 到模板 ID 的自动绑定。Agent 仍须按 Manifest 和模板元数据核实资产是否已实现、兼容当前容器：

| 学习页面职责 | 可优先评估的现有资产 | 当前边界 |
| --- | --- | --- |
| 课程主题与学习路线 | `html.single-page.cover.editorial-v1`、`html.single-page.agenda.route-v1` | 可表达课程主题和章节路线，但没有专用学习目标模板 |
| 概念/机制讲解 | `html.single-page.content.method-v1` | 可表达步骤和方法；概念地图、概念关系专页尚未登记 |
| 例子、案例与依据 | `html.single-page.content.evidence-v1` | 适用于带来源/边界的证据；并非所有教学例子都应伪装成证据表格 |
| 学习者练习、自检与讨论 | 暂无专用单页或交互组件 | 需在页面计划中标记缺口并选择可行的通用内容组织；不得宣称已有互动练习能力 |
| 小结、迁移与后续行动 | `html.single-page.closing.action-v1` | 可以承载迁移任务；需把“学习者下一步”与项目行动责任区分开 |
| 来源与扩展阅读 | `html.single-page.appendix.source-register-v1` | 用于来源登记和补充材料 |

## 目标

让学习者在已有认知基础上理解一个概念、方法或实践对象，能够复述关键机制，参与讨论，并把理解迁移到新的问题或实践中。

## 内容结构

```text
学习目标与先修知识
  -> 问题引入与概念地图
  -> 概念/机制的分步解释
  -> 具体例子或案例
  -> 练习、思考题或讨论提示
  -> 阶段小结与自检
  -> 迁移任务、下一步和来源
```

以上是默认内容路径，不要求每门课机械包含相同页数或标题。简报对齐时可以根据学习目标、省略项和使用方式调整，但应记录调整理由。原文主张、原文数据、讲者归纳和团队判断要分开标注。讲者备注与读者可见内容必须分别确认，不能把未授权信息藏进备注。

## 输入

- 学习对象和使用情境；
- 学习者的先修知识和预计学习时间；
- 允许引用的文档、链接、数据和示例；
- 学完后希望学习者能解释、判断或完成的动作。

## 内容与表达规则

### 正文、备注和附录分层

正文呈现主题、核心判断、帮助理解的图例，以及会影响结论的必要条件。讲者串场、扩展解释、完整出处可以进入默认隐藏的讲者备注；长证据、完整来源索引和推导可以进入附录。来源不必在每页固定显示为小字页脚，但应通过稳定页面 ID 关联到 `source-map.json`，让核对者找到具体出处。

“隐藏”只是演示时的显示状态，不是权限控制。备注与 HTML 一起交付，未经授权的信息不能放入正文、备注或附录。样本、实验设置、比较基线等会改变结论含义的条件不能一律移到备注；可以用简洁正文保留条件，详细口径放在后层。

### 精确结论与辅助解释

同一页可以有以下层级，但不要求每页全部出现：

| 层级 | 职责 | 中性教学示例 |
| --- | --- | --- |
| 定义 | 说明对象是什么及适用边界，忠实于来源 | “本示例把检查点定义为任务中可供后续恢复的状态记录。” |
| 核心判断 | 用准确、可核对的一句话表达本页要点 | “状态可恢复与任务已完成是两个不同的判断。” |
| 辅助解释 | 用自然语言、例子或类比帮助理解，不扩张结论 | “先记住做到哪一步，下次才容易接着做。” |
| 讲者备注 | 保存解释步骤、串场和追溯，不承担必须被学习者看到的结论 | “请先让学习者说出恢复时需要哪些信息，再展示示例。” |

不要用口号替代定义；不要为了严谨把整段来源说明都堆进正文。类比、讲者归纳和来源原话应分别标记，辅助解释可以更自然，但不能改变核心概念。

### 问题提出与结尾回应

需要回扣某个目标时，应先在前文明确提出它，再安排解释、例子和回应。逐页计划用稳定的 `id` 标识页面，用 `responds_to` 引用前面的问题页；显示页码按当前顺序生成，不用“第六页”“前页”等易失效文字作为唯一关联。不是所有页面都必须回扣，也不需要为此建立复杂知识图谱。

### 受众、深度与节奏

简报说明学习者已具备什么基础、本轮要达到哪一层理解、预计分享时长和参与方式。按时间预算给解释、案例、讨论和回顾留出空间；根据受众基础决定哪些术语需要展开，哪些推导只放附录。不统一限定页数或每页字数。实际讲解中出现跳步或超时，应调整范围和拆页，不能靠缩小字体或隐藏正文解决。

### 逐页认可与分阶段制作

用户认可某个封面、案例页或某一轮视觉方向，只确认该范围。修订记录应列出目标页面 ID、继承的基线版本、认可范围与实际反馈出处；不得把“这一页可以了”当作整门课验收。已认可的非目标页面应保持不变，确定性差异检查可以发现变化，但不能代替用户确认。

允许先完成封面、目录样式或某一章。目录标题和未制作章节可作为明确登记的占位，但必须在页面计划与交接记录中区分“已制作”“占位”“已讨论未制作”；不能把模板存在、规划完成或测试通过说成内容已完成。暂停和恢复复用任务循环的 `pause` / `resume`，不另建一套课程状态机。

记录样例见 [HTML 任务记录样例](../../infrastructure/html/examples/records/README.md)。样例是记录结构，不是实际用户认可或项目事实；任务状态仍由任务工具管理的 `task.json` 唯一确定。

## 现有资产与缺口

当前可以使用 `expression.html-production` 与 `html.container.presentation-deck-v1`，组合封面、目录、章节过渡、方法、证据、结尾和附录页面。学习目标、概念地图、练习/自检尚未登记为专用单页模板或交互能力；制作时必须把缺口记录为待补基础设施，不得伪称已有能力。

## 验收

- 学习目标可观察，能判断学习者要理解或完成什么；
- 结构按学习者理解顺序组织，而不是只按来源文章顺序压缩；
- 关键概念有解释与例子；至少有一个练习、思考题、讨论提示或自检动作；
- 结尾说明如何把理解迁移到下一项实践；
- 事实、来源、归纳和待验证判断有清晰边界；
- 问题与回应关系能追溯，已认可范围与未制作范围清楚，暂停后可以根据文件续作；
- HTML 结构、离线资源、响应式、交互和打印检查按主工作流执行。
