# 面向合作方的项目进展沟通

## 目标

让项目外部合作方或客户在一个明确时间点理解项目处于什么阶段、哪些工作主线已经推进、证据和边界是什么、接下来需要怎样协作。

## 内容结构

```text
当前判断与项目范围
  -> 阶段状态和时间口径
  -> 工作主线进展
  -> 证据、数据和来源边界
  -> 风险、依赖和待确认事项
  -> 下一步、责任人和时间点
```

页面应便于扫描和对齐，不把候选判断写成已确认事实。若目标变成选择方案或作出正式决定，应改用单独的方案评审或决策支持场景，不继续沿用本画像。

## 输入

- 项目上下文、阶段目标和当前状态；
- 工作主线、里程碑、证据、风险和依赖；
- 合作方可见范围与不可公开内容；
- 下一步行动、责任人和期望时间。

## 现有资产

连续阅读可以选择 `html.project-report-v1`；需要现场逐页讲解时可以使用 `html.presentation-deck-v1` 或逐页容器与单页组合。状态、指标、证据、来源和下一步组件可按模板契约使用。

## 验收

- 读者能在开头理解项目、阶段和当前判断；
- 每条进展都有时间口径、证据或明确的待确认状态；
- 风险、依赖和表达边界没有被进展叙述掩盖；
- 下一步包含动作、责任人和时间点；
- 合作方看完后知道需要继续了解、反馈或配合什么；
- HTML 结构、离线资源、响应式、交互和打印检查按主工作流执行。
