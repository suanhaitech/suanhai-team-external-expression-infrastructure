# 面向合作方的项目进展沟通

## 目标

让项目外部合作方或客户在一个明确时间点理解项目处于什么阶段、本周期发生了哪些关键变化、各工作主线如何共同影响项目目标，以及接下来需要怎样协作。周期性汇报由项目经理作为统一主汇报人组织总叙事；这表示项目经理对汇总、口径和跨线解释负责，不表示其可以替代主线负责人核验技术事实或作出专业结论。

## 内容结构

```text
项目范围、汇报周期和信息截止时间
  -> 项目经理的总体判断与相对上期的变化
  -> 各工作主线的本期结果、证据、结论和限制
  -> 跨主线依赖、里程碑影响和整体风险
  -> 需要双方确认/支持的事项及其影响
  -> 下周期目标、负责人、时间点和可核对结果
```

总体判断先回答“项目整体发生了什么变化、这对目标和里程碑意味着什么”，再下钻到主线细节。主汇报人应把不同主线的输入整理成项目级解释，而不是把各负责人原文顺次拼接成工作清单；技术细节和长证据可保留在已授权的附件中并由总报告链接。若本期没有可核验的主线更新，应标记为“待确认/未收到更新”，不能推断为无进展。

页面应便于扫描和对齐，不把候选判断写成已确认事实。不同主线的数据截止日或状态口径不一致时应分别注明；缺少证据时保留限制。若目标变成选择方案或作出正式决定，应改用单独的方案评审或决策支持场景，不继续沿用本画像。

## 输入

- 上期汇报、当前项目目标/里程碑和本期汇报周期；
- 每条工作主线负责人提交的本期结果、证据位置、阶段结论/限制、风险依赖和下期目标；
- 项目经理对主线输入的确认、跨线关系与整体影响判断；
- 各项数据的统计范围、更新时间、来源版本及待核验状态；
- 合作方可见范围、附件授权、会议用途和需要对方确认/支持的事项。

## 现有资产

连续阅读和会前传阅可以选择 `html.project-report-v1`，按已确认内容计划调整章节；需要现场逐页讲解时，优先使用 `html.container.presentation-deck-v1` 与下表中的单页自由组合，也可使用兼容预设 `html.presentation-deck-v1`。技术详证作为获准的附件链接。状态、指标、证据、来源和下一步组件可按模板契约使用。

## 从场景到页面的映射

必须明确总体判断与时间口径、支持判断的证据/限制、项目影响、下周期结果和责任；这些是内容要求，不要求每项恰好占一页。周期汇报默认对照上期计划与本期实际；缺少上期基线时明确注明，不能凭空编造变化或完成率。

| 内容职责 | 默认候选资产 | 场景验收信号 |
| --- | --- | --- |
| 项目、周期、受众、主汇报人 | `html.single-page.cover.editorial-v1` | 开场可识别本次沟通的对象与范围 |
| 总体判断、关键变化、里程碑影响 | `html.single-page.content.project-overview-v1` | 能先理解项目整体，再下钻到主线 |
| 每条主线的上期目标、本期结果、证据/限制、下期目标 | `html.single-page.content.workstream-update-v1`，按需重复 | 结果与证据一致，负责人和项目影响明确 |
| 跨线依赖、整体风险、需要双方配合的输入 | `html.single-page.content.dependencies-v1` | 说清输入输出、受影响目标、解除条件及请求期限 |
| 下周期结果、行动与责任 | `html.single-page.closing.action-v1` | 动作有负责人、时间点和可核对的完成条件 |
| 来源、长证据、技术细节 | `html.single-page.appendix.source-register-v1` 或已登记的证据/方法页 | 主报告可追溯，且不过载主讲画面 |

默认采用“总体 → 主线 → 跨线 → 行动”的讲述顺序，主线页可重复，数量由真实主线和现场时长决定。目录、章节过渡、方法详解和来源附录按需选择；没有相关依赖或请求时可省略独立页面并说明核对结果。不能因为旧样例有三条工作线，就把三条写成工具约束。完整内容计划示例和试用验收见 [`项目总汇报设计`](../../docs/project-progress-report-design.md)。

## 验收

- 读者能在开头理解项目范围、本期总体判断、相对上期的关键变化和信息截止时间；
- 每条主线均说明本期结果、证据、结论/限制和责任人；未收到或未核验的信息被显式标记；
- 主线之间的输入输出关系、依赖或对里程碑的影响有项目级解释，而非只并列状态；
- 每项协作请求说明需要谁确认/提供什么、期望时间和对项目推进的影响；
- 下周期安排以结果或验收证据为目标，并写明负责人和时间点；
- 技术事实由相应负责人核验，项目经理负责整体口径与叙事，公开范围和发布授权单独确认；
- 合作方看完后知道需要继续了解、反馈或配合什么；
- HTML 结构、离线资源、响应式、交互和打印检查按主工作流执行。

新 HTML 任务默认采用分页组合（`html.container.presentation-deck-v1` + `page-plan.json` + `html.single-page.*`），服务现场逐页讲解。用户明确要求连续阅读、传阅或查阅时采用长页；既有长页保持兼容。容器选择与空白模板/完整报告是独立维度；Agent 主动推荐资产，记录候选与选用资产、定制理由和验收信号。
